    - Define `WsMessageType` union: 'priceTick' | 'equityUpdate' | 'orderFilled' | 'orderSubmitted' | 'orderCancelled' | 'orderFailed' | 'circuitBreaker' | 'engineStarted' | 'engineStopped' | 'riskUpdate' | 'snapshot' | 'error' | 'reconciliation' | 'shutdown'
    - Define `WsMessage { type: WsMessageType; payload: unknown; timestamp: number }`

    - Define API response interfaces for each endpoint (use string fields for all financial values -- no Decimal objects in JSON)

    - Export `WsBroadcaster` class with:
      - `private clients = new Set<WebSocket>()` (import WebSocket type from 'ws')
      - `addClient(ws: WebSocket)` -- adds to set, registers close handler to remove
      - `removeClient(ws: WebSocket)` -- removes from set
      - `broadcast(type: WsMessageType, payload: unknown)` -- JSON.stringify and send to all clients with readyState === 1 (OPEN)
      - `getClientCount(): number`
    - Server-side ping/pong: when addClient is called, set up a 30-second ping interval, clear on close

    Create `src/dashboard/server/ws/handler.ts`:
    - Export async function `wsHandler(app: FastifyInstance, deps: { broadcaster: WsBroadcaster; getSnapshot: () => unknown; onCommand: (cmd: WsCommand, ws: WebSocket) => void })`
    - Register `app.get('/ws', { websocket: true }, ...)` route
    - On connection: add client to broadcaster, send initial snapshot, register message handler that parses JSON and calls onCommand
    - On close: client auto-removed by broadcaster's close handler

    - Register @fastify/cors (in dev mode only), @fastify/websocket, @fastify/static (prod mode, serves from dist/dashboard)
    - Instantiate WsBroadcaster
    - Wire engine events to broadcaster: for each engine, subscribe to all LiveEngineEvents and call `broadcaster.broadcast(eventName, data)`
    - Register wsHandler
    - Register all REST route modules (from Task 2) under /api prefix
    - Return the Fastify instance and a `close()` method

  <action>
    Each route module exports an async function `(app: FastifyInstance, deps: RouteDeps) => void` that registers routes on the app.

    **sessions.ts:**
    - `GET /api/sessions` -- calls both LiveStateStore.listSessions() and SessionStore.listSessions(), returns combined array with mode discriminator. Supports optional `?status=running|stopped` query param.
    - `GET /api/sessions/:id` -- returns single session by ID (try live store first, then paper store)

    **trades.ts:**
    - `GET /api/sessions/:id/trades` -- calls getSessionTrades(id). Support query params: `?sort=timestamp&order=asc|desc&limit=100&offset=0` for pagination/sorting.

    **equity.ts:**
    - `GET /api/sessions/:id/equity` -- calls getSessionEquity(id), returns array of {timestamp, equity} points for charting.

    **positions.ts:**
    - `GET /api/positions` -- returns all open positions across all active sessions. Derives from LiveStateStore by finding orders with ENTRY purpose that have no matching EXIT. Include unrealized PnL calculation placeholder (currentPrice - entryPrice * quantity).

    **risk.ts:**
    - `GET /api/risk` -- returns current risk status: drawdown percentage, exposure percentage, active circuit breakers. Reads from RiskManager.getCircuitBreakerState() if available. Also returns risk config thresholds (maxDrawdown, maxExposure from config) so frontend can configure gauge zones.
    - `GET /api/risk/events` -- returns recent circuit breaker events from risk manager log (last 50).

    **strategies.ts:**
    - `GET /api/strategies` -- returns list of active engines from ActivationBridge.getActiveEngines() with status (running/stopped), strategy name, session ID, pair, timeframe.
    - `POST /api/strategies/:name/start` -- starts a strategy via engine factory callback. Returns 200 with session info.
    - `POST /api/strategies/:name/stop` -- stops a strategy via ActivationBridge engine handle stop(). Returns 200 on success.

    **kill-switch.ts:**
    - `POST /api/kill-switch` -- iterates all active engine handles from ActivationBridge and calls stop() on each. Returns 200 with count of engines stopped. This is the REST fallback; the primary kill switch goes through WebSocket for lower latency.

    All financial values in responses MUST be strings (use toApiTrade, toApiSession helpers from types.ts). Use Pino logger (createModuleLogger) for request logging.
  </action>
