**Verify src/perp/intx-client.ts WebSocket implementation against spec:**

**Subscription routing (critical — FCM uses two WebSocket endpoints):**
- `ticker` channel subscribes via `'advTradeMarketData'` (public endpoint) — NOT advTradeUserData
- `futures_balance_summary` channel subscribes via `'advTradeUserData'` (authenticated)
- `user` channel subscribes via `'advTradeUserData'` (authenticated)
- Both authenticated channels use the same `WebsocketClient` instance (one `ws` handles both)

**ticker update handler:**
- Handles both flat `{ type: 'ticker', price, product_id }` and nested `{ channel: 'ticker', events: [{ tickers: [...] }] }` structures
- Emits `markPrice` event with: `instrument` (product_id), `markPrice` (price field), `indexPrice` (same price — FCM ticker does not split mark/index; note this in a code comment), `timestamp: Date.now()`, `isStale: this._isStale`
- Only emits if both `productId` and `price` are present (guard)

**futures_balance_summary handler:**
- Extracts `funding_hold` from `data?.events?.[0]?.fcm_balance_summary`
- Emits `fundingRate` with: `instrument: 'FCM'`, `fundingRate: summary.funding_hold`, `isFinal: false`, `timestamp: Date.now()`, `isStale: this._isStale`
- Only emits if `funding_hold` is present

NOTE: FCM's futures_balance_summary channel provides an account-level funding_hold aggregate, not separate per-instrument 8-hour funding rates for BTC-PERP and ETH-PERP. This is an FCM API limitation — no per-instrument funding rate WebSocket channel exists. The aggregate funding_hold is sufficient for FundingRateTracker (phase 31). Verify the existing implementation emits instrument='FCM' (not instrument='BIP-20DEC30-CDE') and that this is documented with a code comment in intx-client.ts near the fundingRate emit, e.g.: `// FCM limitation: futures_balance_summary yields an account-level funding_hold aggregate, not per-instrument 8h funding rates`

**Stale-data flagging:**
- `on('close')` handler sets `this._isStale = true` before emitting `disconnected`
- `on('open')` handler sets `this._isStale = false` and resets `reconnectAttempts = 0`
- Reconnect timer callback sets `this._isStale = false` after re-subscribing

**Exponential backoff reconnect:**
- Constants: `INITIAL_DELAY_MS=1000`, `BACKOFF_MULTIPLIER=2`, `MAX_DELAY_MS=30000`, `JITTER_FACTOR=0.2` (±20%), `MAX_RECONNECT_ATTEMPTS=10`
- Formula: `base = min(INITIAL_DELAY_MS * 2^(attempts-1), MAX_DELAY_MS)`, `jitter = base * 0.2 * (Math.random()*2-1)`, `delay = round(base + jitter)`
- After exceeding MAX_RECONNECT_ATTEMPTS: emits `reconnectFailed({ attempts })`, sets `stopped=true`, does NOT schedule another timer
- `stop()`: sets `stopped=true`, clears `reconnectTimer`, calls `ws.closeAll()`, sets `ws=null`
- `_scheduleReconnect()`: checks `if (this.stopped) return` at entry

**package.json — confirm `"perp:status"` npm script exists:**
- Expected entry: `"perp:status": "tsx src/cli/perp-status.ts"`
- If missing, add it to the `"scripts"` section

Fix any mismatch found. If all correct, make no changes — document as verified.
